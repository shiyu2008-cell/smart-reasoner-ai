# AI简历优化平台功能完善计划

## 项目现状分析
- 当前使用Next.js + React + Better Auth（无状态配置）
- 认证系统：Better Auth，用户数据存储在cookie中
- 机会管理：使用sessionStorage存储评估和优化次数
- 导航栏：存在"招聘趋势报告"链接需移除
- 支付流程：pricing页面有购买按钮但无实际支付功能

## 任务分解与实施方案

### 任务1：构建用户设置界面和支付界面
#### 1.1 用户设置界面 (`/app/settings/page.tsx`)
- **功能**：显示用户账户信息、使用统计、兑换码历史
- **内容**：
  - 用户基本信息（邮箱、用户名）
  - 剩余使用次数统计（评估/优化）
  - 已使用兑换码记录
  - 账户设置选项
- **集成**：
  - 使用Better Auth的`useSession`获取用户信息
  - 从sessionStorage读取使用次数
  - 从localStorage读取兑换码记录

#### 1.2 支付界面 (`/app/payment/[plan]/page.tsx`)
- **功能**：显示支付选项和"待开发"提示
- **路由结构**：
  - `/payment/new-user` - 新人1元试用
  - `/payment/professional` - 专业套餐
  - `/payment/monthly` - 月卡
  - `/payment/annual` - 年卡
  - `/payment/mega-pack` - 超大包
- **UI要求**：
  - 显示所选套餐详情
  - 清晰的"待开发"提示文字
  - 返回pricing页面的链接

#### 1.3 导航更新
- 在导航栏添加"设置"链接（/settings）
- 更新pricing页面按钮的href指向对应支付页面

### 任务2：移除"招聘趋势报告"功能
#### 2.1 前端界面清理
- 从`app/layout.tsx`导航栏中移除"招聘趋势报告"链接
- 检查并删除`/app/trends/`目录（如果存在）

#### 2.2 后端关联清理
- 检查是否有`/api/trends`相关API路由并移除
- 确保无其他文件引用该功能

### 任务3：完善新用户注册福利机制
#### 3.1 注册流程增强
- **修改注册页面**：注册成功后设置初始使用次数
  - 评估次数：3次（原为2次）
  - 优化次数：3次（原为1次）
  - 总计：6次完整机会（3次评估+3次优化）

#### 3.2 防重复机制
- **localStorage标记**：`hasReceivedRegistrationBonus: true`
- **检查逻辑**：注册时检查标记，避免重复发放
- **dashboard集成**：加载时检查标记并设置次数

#### 3.3 可靠性保障
- **双重验证**：sessionStorage + localStorage双重记录
- **错误处理**：添加try-catch和fallback机制
- **数据恢复**：sessionStorage损坏时的恢复逻辑

### 任务4：添加兑换码功能
#### 4.1 前端界面 (`/app/dashboard/page.tsx`)
- **兑换码输入组件**：
  - 输入框 + 兑换按钮
  - 实时验证反馈
  - 成功/错误提示

#### 4.2 后端API (`/app/api/redeem/route.ts`)
- **API端点**：`POST /api/redeem`
- **请求参数**：`{ code: string }`
- **验证逻辑**：
  - 验证兑换码有效性（预设"万柏666"）
  - 检查用户是否已使用过该兑换码
  - 返回兑换结果和奖励信息

#### 4.3 兑换码规则
- **预设兑换码**："万柏666" → 3次完整机会
- **使用限制**：每个用户每个兑换码只能使用一次
- **奖励类型**：支持次数或礼包兑换
- **存储机制**：localStorage记录已使用兑换码

#### 4.4 奖励发放
- **增加次数**：更新sessionStorage中的剩余次数
- **记录历史**：保存兑换记录到localStorage
- **实时更新**：兑换成功后立即更新UI显示

## 技术实现要点

### 数据存储策略
1. **sessionStorage**：临时使用次数（页面会话有效）
2. **localStorage**：持久化标记和兑换记录
3. **Better Auth Cookie**：用户身份信息

### 错误处理与边界条件
1. **存储异常**：localStorage/sessionStorage不可用时的fallback
2. **网络错误**：API调用失败的用户友好提示
3. **数据验证**：输入验证和防重复检查
4. **类型安全**：完整的TypeScript类型定义

### 代码质量保障
1. **TypeScript检查**：确保类型安全
2. **ESLint验证**：代码风格统一
3. **构建测试**：确保编译通过
4. **功能测试**：手动验证各功能流程

## 智能体协作策略
1. **Frontend Architect**：主导任务1、4的前端界面开发
2. **Backend Architect**：处理任务4的API路由实现
3. **Debug-Coder**：协助调试和解决实现过程中的问题

## 实施顺序建议
1. 任务2：移除"招聘趋势报告"功能（最简单）
2. 任务3：完善注册福利机制（基础功能）
3. 任务1：构建用户设置和支付界面（界面开发）
4. 任务4：添加兑换码功能（前后端集成）

## 预期成果
1. 完整的用户设置和个人中心
2. 清晰的支付流程（带开发状态提示）
3. 稳定可靠的新用户福利机制
4. 灵活的兑换码系统
5. 干净的代码结构，无冗余功能

## 风险与应对
1. **无状态限制**：使用客户端存储替代数据库
   - 应对：实现合理的数据同步和恢复机制
2. **浏览器兼容性**：localStorage/sessionStorage可用性
   - 应对：添加兼容性检查和fallback
3. **用户数据丢失**：浏览器清理导致数据丢失
   - 应对：清晰的用户提示和重新获取机制
